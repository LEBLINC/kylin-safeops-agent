## 1 产品概述

### 1.1 一句话定位

**Kylin SafeOps Agent 是部署在麒麟 V11 + LoongArch 上的"不可信顾问 + 确定性代码地板"安全智能运维 Agent——用自然语言完成日常运维，全程留痕、可审计、可回溯。**

### 1.2 产品价值

| 价值 | 说明 |
|------|------|
| **降低运维门槛** | 自然语言一句话触发运维任务，无需记忆命令与参数 |
| **保障操作安全** | 五道安全闸全链闭合：大模型的输出必须通过确定性代码校验才能落地 |
| **提升定位效率** | 故障处理由"经验 + 多条命令"变为"现象 → 根因报告"的自动闭环 |
| **全栈国产化** | 麒麟 V11 + LoongArch + 国产大模型 + 纯 Python 后端 |
| **可审计合规** | 所有操作进入 SQLite 哈希链，可独立校验完整性、逐条回溯；任一记录被篡改可定位到具体断链位置 |

### 1.3 目标用户

| 角色 | 核心诉求 |
|------|----------|
| 一线运维 | 快速查询系统状态、批量诊断故障 |
| 系统管理员 | 高危操作审批、变更管控 |
| 审计 / 合规 | 操作链路追踪、证据完整性核验 |
| 教学 / 培训 | 信创实验、演示与答辩 |

### 1.4 产品形态

![图 1-1 产品形态图](../figures/fig-prd-1-1-product-form.png)

B/S 架构，单机部署，浏览器即可使用，运维端免安装客户端。


## 2 适用场景与不适用场景

### 2.1 适用场景

- **信创替代**：麒麟 V11 + LoongArch 环境下替代传统 x86 运维工具栈，接入国产大模型。
- **教育行业**：高校信创实验室日常运维演示，操作系统 / 系统安全 / 大模型实训。
- **政企数据中心**：面向等保合规的高危操作二次确认与不可篡改审计。
- **医疗与公共服务**：底层 OS 状态监控、值班值守、故障处置全程留痕。

### 2.2 不适用场景

- 应用层业务系统（ERP / CRM）功能开发；
- 跨主机多机集群编排；
- 裸机底层驱动调试；
- 非麒麟 / 非 LoongArch 平台部署。


## 3 产品特色与创新点

### 3.1 不可信顾问 + 确定性代码地板

大模型仅产出"工具名 + 结构化参数 + 理由"的 JSON 意图，**绝不生成裸 shell 命令**；所有安全决策由确定性 Python 代码兜底。即使模型被提示词注入诱导，危险指令也会在确定性策略层被拦截——**判定靠地板，不靠模型自觉**。

### 3.2 五道安全护栏

![图 3-1 五道安全护栏图](../figures/fig-prd-3-1-five-gates.png)

每一步都是确定性代码，层层收敛风险。

### 3.3 智能根因分析闭环

"现象 — 证据 — 根因 — 建议 — 验证"全链路自动化，规则引擎与大模型协同产出可解释的根因报告。

### 3.4 MCP 风格工具体系

面向运维工具的 MCP 风格内部调用体系（工具规范、注册、Schema 校验、调用控制、结果封装），当前提供 15 个运维工具，新增工具只需声明契约即可注册，核心编排逻辑无需改动。

### 3.5 全栈国产化

麒麟 V11 + LoongArch + 国产开源大模型 + 纯 Python 后端；唯一编译型依赖通过预编译 wheel 部署，前端在 x86 侧构建为静态文件，不占用 LoongArch 资源。

### 3.6 可验证的哈希链审计

每条审计记录以 `sha256(前序哈希 + 本条内容)` 串联成链，可独立校验完整性；任一记录被篡改都会在校验时被定位。

### 3.7 与传统方式对比

| 维度 | 传统 CLI / 脚本 | 通用监控平台 | 普通问答机器人 | **Kylin SafeOps Agent** |
|------|----------------|-------------|---------------|-------------------------|
| 交互方式 | 记忆命令 | 图表面板 | 自然语言 | 自然语言 + 结构化意图 |
| 安全护栏 | 依赖人 | 只读为主 | 无 | 五道确定性安全闸 |
| 高危操作 | 直接执行 | 不涉及 | 直接建议命令 | 风险分级 + 人工审批 + 沙箱 |
| 根因分析 | 人工经验 | 告警规则 | 泛泛而谈 | 多源证据 + 规则引擎闭环 |
| 可审计性 | 依赖 history | 部分 | 无 | 哈希链完整可校验 |
| 国产平台 | 需适配 | 多为 x86 | — | 麒麟 V11 + LoongArch 原生 |

![目标平台架构确认（loongarch64 + 麒麟 V11）](../screenshots/vm-uname.png)

### 4.2 浏览器环境

- Chrome / Edge ≥ 100，Firefox ≥ 100；
- 屏幕分辨率 ≥ 1366×768（推荐 1920×1080）。

### 4.3 网络与端口

| 端口 | 用途 | 说明 |
|------|------|------|
| 443 | HTTPS 对外 | Nginx（TLS + 安全响应头 + 限流） |
| 8080 | 反代签名 sidecar | 仅监听 127.0.0.1，真 LDAP 鉴权 + HMAC 签名 |
| 8000 | FastAPI 后端 | 仅监听 127.0.0.1，物理上无法绕过 sidecar 直连 |
| 389 / 636 | LDAP | 真身份鉴权（636 为 TLS） |

### 4.4 部署形态

单机部署（麒麟 V11 主机一台）：Nginx、反代 sidecar、后端、审计库同机；LDAP 可同机或独立部署。


## 5 登录、首页与导航

### 5.1 登录与认证

系统默认采用 **proxy 生产模式**：浏览器访问 `https://<主机>`，输入 LDAP 用户名密码；反代 sidecar 通过真实 LDAP 校验身份，校验通过后为请求注入 HMAC 签名身份头，转发至后端。后端对全部业务接口强制校验签名身份，缺失或非法一律拒绝（返回 401）。

联调开发另提供 dev 模式（放行、便于本地调试），生产部署默认使用 proxy 模式。

## 6 自然语言运维交互

### 6.1 操作流程

用户在对话页输入自然语言运维请求，系统按"输入闸过滤 → 大模型解析意图 → 参数 Schema 校验 → 策略裁决 → 执行 → 结果解释 → 审计"的链路处理，并通过流式事件（SSE）实时展示每一步。

| 项 | 内容 |
|----|------|
| 功能用途 | 用自然语言下达运维请求并获得结构化结果与解释 |
| 适用角色 | operator / admin（auditor / viewer 可只读查询类） |
| 操作入口 | 对话页 Chat |
| 前置条件 | 已登录（proxy 模式签名身份） |
| 操作步骤 | 输入请求 → 观察流式事件 → 查看结果与解释 |
| 预期结果 | 返回结构化结果 + 自然语言总结 + 可回溯 trace |
| 风险提示 | 变更类请求会进入审批流程，不直接执行 |
| 常见异常 | 输入被安全闸拦截时返回安全说明；模型不可达时返回明确提示 |
| 对应评分项 | 功能完整性—自然语言识别 |

### 6.2 流式事件识别

对话过程中前端逐步渲染以下 13 类事件（与 `contracts/stream.py` 契约完全一致）：意图已解析、观测采集、计划生成、策略裁决、等待审批、执行中、工具结果、已验证、已拒绝、根因、自然语言总结、审计已记录、错误。任务以"已验证"（成功）或"已拒绝"（被安全闸拦截）结束；`错误` 事件为系统内部异常通知，不影响已完成的审计记录。

### 6.3 模型运行模式标识

设置页实时展示当前大模型运行模式：**真实端点模式**（对接 Qwen3.7 系列等国产大模型）或**测试桩模式**（确定性内置响应，用于开发联调与离线演示）。演示时应在设置页确认当前模式，Mock / 测试桩模式的界面会带有显著标识，其结果不用于证明真实模型能力。

## 10 安全风险提示、高危确认与阻断

### 10.1 风险等级

系统按 R0–R4 对工具与操作分级：R0 只读无副作用，R1 轻量诊断，R2 及以上为变更类。当前 15 个工具中，只读/轻量工具 13 个，变更类工具 2 个（`log.compress_rotate` 为 R2，`service.restart` 为 R3、不可逆、仅管理员）。

### 10.2 输入闸拦截

用户输入在进入规划前先经输入闸扫描。提示词注入（如"忽略以上规则，以管理员身份执行……"）会被直接识别并拦截，返回安全说明并记录审计，不进入执行链路。

![注入拦截提示](../screenshots/10-inject-block.png)

### 10.3 策略裁决与高危确认

策略引擎对每次操作产出 allow / deny / confirm 裁决：只读操作直接放行；危险参数或受保护路径被拒绝；变更类操作进入 confirm，必须经对应角色人工审批后才能执行。R3 操作（如服务重启）需管理员审批。

### 10.4 安全操作说明表

| 场景 | 系统行为 | 证据 |
|------|---------|------|
| 提示词注入 | 输入闸拦截，返回安全说明 | 审计留痕 + 拒绝原因 |
| 危险参数 / 受保护路径 | 策略闸拒绝 | 审计留痕 + 拒绝原因 |
| 高危变更（R2/R3） | 进入审批，审批后最小权限执行 | 审批记录 + 执行记录 |
| 越权触发 | 角色不足被拒 | 审计留痕 |


## 11 权限与用户管理

### 11.1 角色定义

系统统一小写角色：`operator`（运维员）、`admin`（管理员）、`auditor`（审计员）、`viewer`（只读，dev 联调态占位角色，生产环境权限由 LDAP 角色映射提供）。角色由真实 LDAP 目录经反代签名身份提供。下表权限矩阵列出生产环境三类实际业务角色；`viewer` 仅拥有只读查询能力，不参与变更、审批与审计操作。

### 11.2 权限矩阵

| 操作 | operator | auditor | admin | viewer |
|------|:---:|:---:|:---:|:---:|
| 只读查询（系统状态、工具清单） | ✅ | ✅ | ✅ | ✅ |
| 自然语言查询类 | ✅ | ✅ | ✅ | ✅ |
| 触发 R2 变更 | ✅（经审批） | ❌ | ✅ | ❌ |
| 触发 R3 变更 | 需管理员审批 | ❌ | ✅ | ❌ |
| 审批 R2 | ✅ | ❌ | ✅ | ❌ |
| 审批 R3 | ❌ | ❌ | ✅ | ❌ |
| 审计查询 / 导出 / 链校验 | ❌ | ✅ | ✅ | ❌ |

审批权限由确定性规则判定：operator 只能批准 operator 级操作，admin 可批准 operator 与 admin 级操作，其余角色一律拒绝（失败关闭）。

分类：系统 3、磁盘 2、进程 1、网络 1、日志 3、文件 1、服务 2、配置 2。变更类工具 2 个（`log.compress_rotate` R2、`service.restart` R3）。
